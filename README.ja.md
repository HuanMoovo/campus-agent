## これは何か

Mens は「学内規定・手続きの質問応答」「ローカルのナレッジベース検索」「学内データサービス」を
1 つのデスクトップアプリにまとめ、文書・データ・鍵を既定で端末内に留めるツールです。
個人の端末で試す・評価する・作り込む用途に向いており、学内の本番システムとして配備する場合は
シングルサインオン、監査、データのコンプライアンス対応を追加する必要があります
（[既知の制限](#既知の制限)を参照）。

### 名前の由来

**Mens はラテン語で、英語ではありません。** ラテン語の *mēns*（属格 *mentis*）は
**心・理性・思考**を意味し、英語の *mental*（心の）や *dementia*（認知症。直訳すると「心から離れた状態」）
の語源でもあります。英語の *men*（*man* の複数形）とはまったく関係がなく、性別を指す意味もありません。
「考えることを助ける道具」という意味を込めた名前で、この学内アシスタントの役割に重ねています。

- **ローカル優先** — ナレッジベース、会話、設定、鍵は端末内（SQLite + ユーザーデータフォルダ）に保存され、外部データベースは不要です。ネットワークがなくても質問応答ができます。
- **事実のまま表示** — 未設定の学内エンドポイントは明確に「デモデータ」と表示し、モデルが使えないときは回答を捏造せずナレッジベースの原文引用に切り替えます。
- **任意のウェブ検索** — 既定は無効。管理者が設定画面で有効化し（キー不要の Bing、または Tavily / 博查）、メッセージごとに切り替えられます。回答は参照元リンクと検索時刻を引用します。
- **クロスプラットフォーム** — Windows はインストーラーですぐ使えます。macOS（Intel / Apple silicon）と Linux（AppImage / deb）は CI がビルドし、スマホ・タブレットはインストール可能なウェブ版（PWA）を使います。
- **オープンソース** — Apache License 2.0（[`LICENSE`](LICENSE) と [`NOTICE`](NOTICE)）。サードパーティ一覧は [`THIRD-PARTY-NOTICES.md`](THIRD-PARTY-NOTICES.md)。

### プロジェクトファイルと確認付き変更

入力欄の「プロジェクト権限」で「読み取り専用 / 変更前に確認」を選択でき、端末内に保存されます。デスクトップの既定は「変更前に確認」、Web 版は常に読み取り専用です。対象は本アプリのネイティブな適用・元に戻す・変更の確定（apply/revert/keep）のみで、プレビュー・変更案・原文のコピー・状態確認・復元アーカイブは引き続き利用できます。確認モードでも操作ごとのシステム確認が必要です。読み取り専用への切り替えは保存前にメインプロセスのメモリ上の変更許可を取り消します。ディスクへの保存に失敗しても変更は許可せず、確認モードは保存成功後に有効になります。保存失敗は画面に表示します。OS・MCP・サンドボックスの権限や完全アクセスを設定する機能ではありません。[権限仕様](docs/superpowers/specs/2026-10-31-project-permission-selector-design.md)を参照してください。

デスクトップのディレクトリ選択画面でプロジェクトを開き、モデルに送るファイルを明示的に選択します。変更案の生成や確認だけでは、プロジェクトを書き換えません。適用できるのは **Windows のローカル NTFS ボリューム上にある既存の UTF-8 ファイル 1 件**で、上限は **12,000 文字・64 KiB・2,000 行**です。上限を超えたファイルは切り詰めずに拒否します。ターミナル実行、複数ファイルの編集、ファイルの新規作成・削除・名前変更コマンド、Git の自動コミットは行いません。

- **操作ごとに確認します。** 適用・取り消し・変更の保持には、それぞれネイティブの確認ダイアログが必要です。取り消せるのは、現在のファイル識別子と全生バイトの SHA-256 が、その変更で生成された版と一致するときだけです。後から編集・置換された場合は上書きせず競合を表示します。「保持」は復元記録を終了して枠を解放する操作で、ファイル自体は変更しません。競合で取り消せない場合も、元の本文をコピーできます。
- **コピーオンライトと明示的な失敗状態。** 元のファイルオブジェクトへ直接書き込みません。書き込みを完了した一時ファイルを、既存の名前を上書きしない 2 回のハンドル経由の名前変更で公開します。これは **クラッシュ時の原子性を保証する処理ではありません**。元の名前が一時的に存在しない区間があり、中断後に一時・バックアップファイルが残って手動復元が必要になる場合があります。処理中・結果不明の場合は記録された状態を確認し、必要に応じて元の本文をコピーしてください。照会がプロジェクトへの書き込みを自動再実行することはありません。
- **端末内に復元記録を保存します。** `dataDir/project-changes.sqlite3` に、選択した元の生バイト、版のハッシュ、操作状態、ルートの物理的な識別子を保存します。ルートの絶対パスを識別情報として保存しません。変更案の期限切れ、プロジェクトを閉じた後、再起動後も記録は残ります。以前の記録の確認・取り消し・元の本文のコピーには、ユーザーが同じ物理ルートを再選択する必要があります。保存した原文は端末内に保持し、復元操作でモデルへ再送しません。原文を含む復元記録は未解決・解決済み各 32 件が上限で、解決済み記録は削除される場合があります。
- **Windows メタデータの対応範囲は限定されています。** 元の所有者・グループ・整合性ラベルは、新しい一時ファイルと一致する必要があります。DACL は保護状態も含めてコピーし、結果を検証します。読み取り専用・システム・再解析ポイント・暗号化・圧縮・スパースの各ファイル、名前付き代替データストリーム（ADS）、その他の未対応属性は拒否します。独自の監査 SACL ルールを持つファイルは対象外です。Mens は `SeSecurityPrivilege` を有効にせず、Windows のセキュリティ記述子全体を保持するとは保証しません。

### 上限付き学内照会タスク（P4A）

現在のメッセージで成績・時間割・取得単位・空き教室を、対応する中国語のコマンドで明示的に照会すると、指定順に最大 **3 種類の内蔵読み取り処理**を実行します。たとえば `查询我的成绩和课表`（成績と時間割を照会）と入力します。同じ照会は重複実行せず、4 種類すべてを指定した場合は一切実行せずに範囲の絞り込みを求めます。履歴・添付・プロジェクト本文・モデルやツールの結果は追加の読み取り権限を与えません。否定、制度の説明、文書やコードの議論は、サービス名を含むだけでは個人データ照会を開始しません。

時間とキャンセルを各照会の開始前と終了後に確認する **20 秒の協調的な予算**があります。厳密なタイムアウトではなく、実行中の同期呼び出しは予算を超えて完了する場合がありますが、キャンセル後の次の照会は開始しません。自動再試行や計画・整形用の追加モデル呼び出しはありません。結果は 1 件 4,000 文字、合計 12,000 文字までで、短縮を明示します。一部が失敗しても成功した結果を残し、各項目でデモか学校 API かを表示します。

通常の HTTP と SSE は同じ実行器を使います。SSE の切断時は進行中の呼び出しを終えてから、完了済みの結果と実際の未完了・失敗状態を履歴へ保存します。折りたたまれた実行詳細に回数・停止理由・短縮の表示があります。永続タスクの再開、MCP の一括実行、ファイル読み取り範囲の拡張は含みません。[P4A 仕様](docs/superpowers/specs/2026-10-31-bounded-campus-reads-design.md)を参照してください。

### モデルの利用

| 方式 | 説明 |
| --- | --- |
| クラウド API | Qwen3 / DeepSeek。各社の API キーと HTTPS アドレスを設定します。鍵は端末内に保存し、画面には再表示しません |
| 自動ルーティング | 分析・比較系の質問は設定済みの DeepSeek を優先し、それ以外は Qwen3 を優先します。手動指定も可能です |
| ローカルモデル | 内蔵カタログ（Qwen3 0.6B / 1.7B、DeepSeek R1 1.5B）。ダウンロード元は Ollama 公式 / Hugging Face / HF Mirror |
| ダウンロードの信頼性 | レジューム、固定バージョン、SHA-256 検証、インポート再試行に対応し、進捗表示とキャンセルができます |
| 降格動作 | キーがない、またはモデルが使えない場合は、ルールによる計画 + ナレッジベース原文の引用に切り替え、その旨を明示します |

### 設定とトークン使用量

- 設定を「一般・モデル・Token 使用量・接続・データとアプリ」に整理しました。白黒のテーマを維持し、グループを切り替えても未保存のモデル・接続設定を保持します。診断の詳細は必要なときに展開できます。
- 使用量は過去 7／30 日の UTC 暦日で、入力・出力・報告済み合計、日次推移、モデル別内訳と日次明細を表示します。記録は機能の導入後からで、過去の会話本文からは推計しません。プロバイダーの請求書とは異なります。
- 未報告の値は「—」とし、一部のみ報告されたリクエストと未報告の件数を区別します。停止・失敗時の値は不完全な場合があり、キャッシュ・推論の内訳を合計へ重複加算しません。接続テストは集計せず、ルールによる回答はモデル呼び出しに数えません。
- 対応する Chat Completions 接続では、モデルの詳細互換設定で `stream_usage` を有効にできます。未対応ゲートウェイとの互換性のため既定は無効です。他の対応プロトコルは、それぞれ返された使用量を読み取ります。
- デスクトップ版は本機アプリのアカウント未所属の記録、ログイン必須のウェブ版はアカウント、匿名ウェブ版はクライアントごとに集計します。会話の削除・再生成でも使用量は消えません。通常のデータベースバックアップに新しい表を含み、旧バックアップも読み込めます。

詳細は[設定と使用量の実装記録](docs/research/2026-10-31-settings-token-usage.md)を参照してください。

### データ・バックアップ・更新

| 機能 | 説明 |
| --- | --- |
| バックアップの書き出し | 既定は format 1：ナレッジベース、会話、モデル、学内エンドポイント設定、SQLite backup API による一貫したスナップショット、各ファイルのサイズ・SHA-256 一覧。「プロジェクト復元原文を含める」を選ぶと format 2 を書き出します |
| バックアップの読み込み | ZIP 全体、一覧、原文資料、データベースを検証してからアプリデータと設定を復元します。任意の原文はコピー専用資料として統合し、追加・重複件数を表示します（zip には鍵ファイルが含まれるため厳重に保管してください） |
| 更新確認 | 管理者が HTTPS マニフェストを設定すると、設定画面から新バージョンを確認してダウンロードページを開けます。空欄なら更新確認は一切通信しません |
| バージョンの整合性 | デスクトップ・フロントエンド・バックエンドのバージョンが一致しない限り、ビルドスクリプトはパッケージを作りません |

原文を含めるチェックボックスは既定でオフです。通常の format 1 にプロジェクト復元原文は含まれません。選択すると `include_project_recoveries=true` を送り、format 2 に既存の復元原文と以前読み込んだ資料を、制限付きの `project-recovery.json` として任意で収録します。パッケージと端末内の資料庫はそれぞれ 256 件・原始バイト合計 16 MiB まで、JSON は 25 MiB までです。原文 1 件の上限は引き続き 64 KiB・12,000 文字・2,000 行です。上限超過は明示的に失敗し、原文を黙って削除しません。

読み込み時は、物理ルート・相対パス・原始バイトのハッシュで重複を除き、独立した `project-recovery-archive.sqlite3` にトランザクションで統合します。資料の操作はコピーのみです。現在の `project-changes.sqlite3`、操作状態、再実行防止の tombstone は置換せず、過去の取り消し権限を復活させず、プロジェクトファイルへ書き込みません。同じ物理ディレクトリをネイティブの選択画面で再選択すると、独立したバックアップ資料欄で原文をコピーできます。別の端末やディレクトリの複製とは自動で関連付けません。どちらの形式にもプロジェクト作業ツリーや実行可能な復元操作状態は含まれません。

旧 format 1 も引き続き読み込めます。重複・未知・不正なパスの ZIP 項目を拒否し、各項目と合計の展開内容を 200 MB までに制限し、適用される一覧のサイズと SHA-256 を検証します。format 2 は一覧と項目の厳密な対応が必要です。アップロードされたデータベースは、トリガーやビューを実行せず、信頼されたアプリの schema で再構築してから反映します。要求ごとに独立した一時ディレクトリを使い、読み込み・書き出しの反映は直列化します。不正な入力はアプリデータ変更前に拒否しますが、実行時の I/O 障害でアプリデータや設定の一部だけが復元される場合があり、データベースとファイルシステムをまたぐクラッシュ時の原子性は保証しません。

### MCP サーバー（外部ツール）

Mens は MCP（Model Context Protocol）クライアントとしても動作し、標準入出力でローカルの
MCP サーバーを起動して、必要なときにそのツールをモデルへ渡します。

- 「MCP」ページでサーバーを登録（コマンド・引数・環境変数）。「テスト」は**実際に子プロセスを
  起動**し、ハンドシェイクとツール一覧の取得を行います。有効かつテスト済みのサーバーのみ公開。
- ツール名は `mcp__サーバー__ツール`。1 回の質問で最大 1 つ呼び出し、結果はそのまま表示します。
- 環境変数（トークンなど）はインターフェース上、キー名とマスクのみを返します。
- 実装は stdio トランスポートのみ（SSE / streamable HTTP は対象外）。

### コマンドライン（CLI）

CLI はデスクトップ版と同じバックエンドとデータディレクトリを共有します：

```bash
python -m app.cli ask "図書館の開館時間"               # 1 回だけ質問（--json 可）
python -m app.cli chat                                 # 対話モード：/quit、/new
python -m app.cli mcp add campus --command npx --args -y <server-package>
python -m app.cli mcp list | test campus | tools --json
python -m app.cli serve --port 8000                    # バックエンドのみ起動
```

### ウェブサイトとしてのデプロイ（任意）

デスクトップ版に加えて、ログイン付きのウェブサイトとしても公開できます：

- リポジトリには `Dockerfile.web`（フロントエンドビルド + FastAPI の単一コンテナ）と
  `render.yaml` が含まれます。Render に GitHub でログインし **New → Blueprint** で本リポジトリを
  選ぶだけです。詳しくは [DEPLOY.md](docs/DEPLOY.md)。
- `AUTH_REQUIRED=true` では、ヘルスチェックと認証系以外のすべての API にログインが必要です。
  パスワードは PBKDF2-HMAC-SHA256 のハッシュで保存し、セッションは HttpOnly Cookie
  （サーバー側はトークンのハッシュのみ保存）です。
- 初回起動時に `AUTH_ADMIN_USERNAME` / `AUTH_ADMIN_PASSWORD` から管理者を作成します
  （パスワード未設定ならランダム生成し、ログに一度だけ出力）。
- 「アカウント」ページではユーザー管理（作成、ロール変更、無効化、削除、パスワード再設定、強制サインアウト）ができ、セルフ登録とセルフパスワード変更にも対応します（`ALLOW_REGISTRATION`、`REGISTER_CODE`）。
- デスクトップ版には影響しません（`AUTH_REQUIRED` の既定はオフ）。

## クイックスタート

### 1. Windows デスクトップ版のインストール

[最新リリース](https://github.com/HuanMoovo/campus-agent/releases/latest) から
`Mens-Setup-1.2.2-x64.exe` をダウンロードして実行します（ユーザー単位インストール、管理者権限は
不要）。スタートメニューまたはデスクトップから起動し、設定画面でモデルの API キーを入力するか
ローカルの Ollama モデルを選べば、すぐに質問できます。

### 2. ソースからのデスクトップビルド

3 プラットフォーム共通のスクリプトで、成果物は `release/` に出力されます：

```bash
# 現在のプラットフォーム（アーキテクチャは自動判定）
python scripts/build_desktop.py

# 対象を指定
python scripts/build_desktop.py --os mac   --arch arm64
python scripts/build_desktop.py --os linux --arch x64

# よく使うオプション
#   --skip-install   インストール済みの依存を使う（高速な再ビルド）
#   --directory      未パッケージのアプリケーションフォルダのみ生成
#   --full-rag       ベクトル検索の依存も同梱（ダウンロードが大きくなります）
```

スクリプトはバックエンド / フロントエンド / デスクトップのテストを実行し、バックエンドを凍結して
から electron-builder でパッケージします。途中で失敗するとインストーラーは生成されません。

### 3. ソースからの実行（ウェブ開発）

Windows では `scripts\install.cmd` をダブルクリックすると、依存のインストール、LangGraph の確認、
バックエンドテスト、フロントエンドのビルドまで実行されます。その後 `scripts\start-backend.cmd` と
`scripts\start-frontend.cmd` を実行し、<http://localhost:5173> を開きます。

手動の場合：

```powershell
# バックエンド（ターミナル 1）
cd backend
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
Copy-Item .env.example .env          # ADMIN_TOKEN を自分で生成した強力な乱数に変更
.venv\Scripts\python -m uvicorn app.main:app --host 127.0.0.1 --port 8000

# フロントエンド（ターミナル 2）
cd frontend
npm install
npm run dev
```

画面は <http://localhost:5173>、API ドキュメントは <http://localhost:8000/docs>。
`backend/.env` の `ADMIN_TOKEN` を設定画面に入力すると、文書とプラグインを管理できます
（トークンはブラウザのセッション内にのみ保持されます）。

### 4. Docker での配備（サーバー・PWA）

```bash
cp .env.example .env      # POSTGRES_PASSWORD と ADMIN_TOKEN を設定
docker compose up -d --build
docker compose logs -f backend
```

<http://localhost:8080> を開きます（スタックは `127.0.0.1:8080` にのみバインドされます）。
スマホのブラウザでこのアドレスを開きホーム画面に追加すると、インストール可能なウェブ版（PWA）
として使えます。

スタックは PostgreSQL + バックエンド + Nginx で構成されます：

| サービス | イメージ | 補足 |
| --- | --- | --- |
| `database` | `postgres:16-alpine` | ヘルスチェック後にバックエンドが起動します。データは `postgres_data` ボリューム |
| `backend` | `python:3.11-slim` | 非 root ユーザーで実行。データは `backend_data`、モデルキャッシュは `model_cache`。`/api/health` でヘルスチェック |
| `frontend` | `nginx:alpine` | ビルド済み Vue アプリを配信し、`/api/` をバックエンドへプロキシします。アップロード上限は 6 MB |

補足：

- ルート `.env` の変数はそのまま渡されるため、ウェブ検索、更新マニフェスト、プラグインの許可ホストもローカル版と同じように設定できます（設定リファレンスを参照）。
- `ENABLE_RAG=true` にするとベクトル検索の依存をイメージに含めます（`INSTALL_VECTOR` ビルド引数）。再ビルドが必要です。
- データは名前付きボリュームに保存されるため、`docker compose down` では残り、`docker compose down -v` で削除されます。更新前にデータベースをバックアップしてください。
- この構成は既定でログインなし（1 台の端末または信頼できるネットワーク向け）。インターネットへ公開する場合は、ルートの `.env` で `AUTH_REQUIRED=true` を設定すると内蔵ログインを有効化できます（初回起動時に管理者を作成、全変数は `.env.example` 参照）。HTTPS とレート制限は別途用意してください。
- **本機で実測済み**（Docker Desktop 29.1.3）：2 つのイメージがビルドされ、database / backend / frontend の 3 サービスが起動して前 2 つがヘルスチェックを通過。`http://localhost:8080/` は 200、`/api/health` は `{"status":"ok",…}` を返し、バックエンドがコンテナ内で **PostgreSQL 16.15** への接続を確認。実ブラウザで「Mens 工作台」が開き、失敗リクエストもページエラーもありません。

### 5. Docker を使わないスマホ・タブレット（PWA）

到達可能な場所にバックエンドを配備し（上記のサーバー配備を参照）、スマホのブラウザでサイトを
開いてホーム画面に追加すると、全画面・専用アイコンのアプリ風に使えます。

### モデルとベクトル検索

- 設定画面でキーを保存し「保存済み設定をテスト」で接続を確認します。Windows では新しいキーを DPAPI で暗号化し、画面には再表示しません。
- ローカルモデル：Ollama をインストールして起動し、設定画面でモデルとダウンロード元を選びます。GGUF は固定バージョンで取得し SHA-256 を検証してから Ollama に取り込みます。モデルファイルはインストーラーに同梱されません。
- ベクトル検索の有効化：

  ```powershell
  cd backend
  .venv\Scripts\python -m pip install -r requirements-ai.txt
  # .env で ENABLE_RAG=true に設定し、バックエンドを再起動して知識ページの「索引を再構築」を押す
  ```

  初回の `BAAI/bge-m3` 読み込みにはダウンロードが必要です。ベクトルの初期化や検索に失敗した場合は、文書を保持したままキーワード検索に降格します。

### 学内データエンドポイント

9 種類のエンドポイントのフィールド、値パス、例は [CAMPUS-DATA.md](docs/CAMPUS-DATA.md) にあります。要点：

- HTTPS の JSON のみ。Bearer トークンと結果パスに対応します。
- 未設定のエンドポイントは明確に表示されたデモデータを返します。本プロジェクトは実際の学校エンドポイント、統合認証、モデルの鍵を**同梱していません**。
- 本番配備には学校が認可したインターフェースと受け入れ検証が必要です。複数人での利用には、シングルサインオン、ユーザーごとの学籍番号の紐付け、操作の監査、レート制限も必要です（[CAMPUS-DATA.md](docs/CAMPUS-DATA.md) と [ARCHITECTURE.md](docs/ARCHITECTURE.md) を参照）。

## アーキテクチャとセキュリティ境界

### 技術スタック

- **フロントエンド**：Vue 3 + TypeScript + Vite + Element Plus + Pinia。ビルド時に依存ごとにチャンクを分割します（メインバンドルは約 71 KB）。
- **バックエンド**：FastAPI + SQLAlchemy + LangGraph。既定は SQLite の単一ファイルで、PostgreSQL も選択できます。
- **デスクトップ**：Electron シェル + PyInstaller で凍結した CPython（ランタイムをインストーラーに同梱）。
- **インストール可能なウェブ版**：マニフェスト、オフラインシェル（service worker）、iOS のセーフエリア対応。

### セキュリティ設計

- **ローカル優先**：デスクトップ版のバックエンドは `127.0.0.1` のランダムポートのみを待ち受け、起動ごとにワンタイムトークンを発行します。シェルは追加のリクエストヘッダーを注入し、Electron の設定を厳格化します（`nodeIntegration:false`、`contextIsolation:true`、`sandbox:true`、`webSecurity:true`、`webviewTag` 無効）。外部ページからこれらの API には到達できません。
- **送信の規律**（プラグイン / ウェブ検索 / 更新確認で共通）：HTTPS の 443 のみ。解決済みで検証済みのグローバルアドレスに接続を固定（DNS リバインディング対策として SNI を保持）。リダイレクト禁止。応答サイズとタイムアウトの上限。システムのプロキシ環境変数は無視（`trust_env=False`）。プライベートアドレスに解決した場合は即座に拒否します。
- **鍵の保存**：Windows は DPAPI。macOS / Linux には同等の仕組みがないため、`0600` 権限の平文ファイル（同一ユーザーのみ読取可）に保存します。この点は [PLATFORMS.md](docs/PLATFORMS.md) に明記しています。
- **バックアップ**：書き出した zip には鍵ファイルが含まれるため厳重に保管してください。復元原文を選ぶとソースの元の内容も含まれます。読み込み時は一覧と内容を検証し、任意の原文はコピー専用資料として統合します。プロジェクトの書き込み権限は復元しません。
- **捏造しない**：デモデータ、検索の降格、ウェブの参照元などの状態は必ず画面に表示します。

## パフォーマンス改善（2026-10-31）

計測した処理の集中箇所を独立モジュールへ分離し、既存の画面・API・権限境界を維持しました。

| モジュール | 現在の動作 |
| --- | --- |
| `frontend/src/ui.ts` | 本番と結合テストで共通のインストーラーを使い、使用する Element Plus 19 コンポーネントと Loading のみ登録。既存 CSS は維持 |
| `ChatMarkdown` とスクロール | 変更のないメッセージは再解析せず、ストリームの最初の文字は即時表示。以降は最大 80 ms に 1 回描画し、完了・失敗・停止時には最終本文を同期反映。スクロール要求も集約 |
| `history_queries.py` | 所有者で絞り込んでからピン・最終メッセージの活動時刻・ID でページ分割。1 ページは SQL 最大 2 回で、回答全文や結果 JSON は取得しない |
| モデル設定 | 状態一覧ごとに新しい処理内スナップショットを読み、保存設定の読み込みを 29 回から 1 回へ削減。次の呼び出しには最新設定を使い、要求をまたぐ鍵のキャッシュは保持しない |
| 計画と復元一覧 | MCP の計画が不要な場合は決定的な分岐を使い、計画用モデル要求を 1 回削減。`ProjectRecoveryList` は更新通知をまとめ、同じルートで同時に 1 回だけ読み取り、途中で変更された結果は破棄して再取得を 1 回予約 |
| `compiled_documents.py` | 不変の分割本文と token 集合を安定した受け入れ方式で保存。既定の上限は 32 MiB / 2,048 件。毎回 SQL の現行文書を読み、内容ハッシュを確認 |

同じ測定条件のビルドで、フロントエンド JS は **1,430,135 → 853,863 バイト（−40.3%）**、gzip は **449,828 → 275,318 バイト**になりました。合成 SQLite の 1,000 会話 / 40,000 メッセージ、1 ページ 50 件では SQL が **1,001 → 2 回**、中央値が **320.293 → 9.083 ms**。合成検索の旧版 / 新版コールド / 新版ウォームは 100 文書で **69.910 / 90.768 / 2.438 ms**、500 文書で **336.510 / 400.848 / 26.599 ms** です。コールド状態や小さい予算では負荷が増える場合があり、SQL の文書取得は全件のままです。これらはビルドと合成マイクロベンチマークの値で、デスクトップ起動時間や実際のモデルサービスの速度ではありません。[結果と制限](docs/research/2026-10-31-performance-refactor-results.md)を参照してください。

**ベクトル索引の互換性：** 文書のバージョンハッシュに独立したドメインと UTF-8 の長さ境界を導入し、タイトル・本文中の NUL による境界の曖昧さを修正しました。旧ベクトルバージョンは無効になり、再索引または索引再構築までは正しいキーワード検索へフォールバックします。認証・プロジェクト許可・NTFS のファイル同一性と完全ハッシュの確認はキャッシュしません。

## 既知の制限

- **macOS / Linux の成果物は実機未検証** — CI が生成したもので、実機へのインストールと実行は未実施です。
- **署名・公証なし** — 発行者の証明書がないため、Windows / macOS の初回起動でシステムの警告が出ることがあります。本格配布の前に署名を設定すべきです。
- **学内連携とシングルサインオン** — 実際の学校エンドポイント、統合認証、モデルの鍵は同梱していません。本番配備には学校が認可したインターフェースと受け入れ検証が必要です。
- **クラウドモデルとウェブ検索** — それぞれ API キーが必要です（ウェブ検索の Bing 経路はキー不要）。検索バックエンドの可用性はネットワーク環境に左右されます。
- **Android / iOS のネイティブアプリ** — 対象外です。理由は [PLATFORMS.md](docs/PLATFORMS.md) に記載しています（Python バックエンドはモバイルストアに同梱できません）。
- **ワンクリック更新** — 更新確認はバージョン差の通知とダウンロードページの表示のみで、自動ダウンロードやサイレントインストールは行いません。
- **複数人での配備** — 現在のデモ会話はランダムなセッション ID をアクセス資格情報にしています。ローカル開発のみに適しており、本番にはユーザー所属の検証、操作監査、レート制限、HTTPS、データベース移行、バックアップ方針が必要です。
